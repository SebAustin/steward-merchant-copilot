# Orchestrator rulings for plan round 2 (binding on all three docs)

These resolve the cross-document contradictions plan-critic found in round 1 (67/100). Where a companion doc owns a topic, PLAN.md references it rather than restating it.

| # | Topic | Ruling | Owner doc |
|---|---|---|---|
| R1 | Doc ownership | AI-QUALITY.md owns models, routing, prompts, Untrusted Text format, evidence-ref grammar, eval commands, budgets and CI eval policy. DESIGN.md owns routes, pages, copy and tokens. PLAN.md owns architecture, data model, invariants, slices, CI/CD and probes. PLAN references the others by section and does not restate them. | all |
| R2 | Failed executions (D7) | `failed` splits into `failed_retryable` (PayPal 5xx, timeout before any response, 429) and `failed_final` (4xx business errors). A retry from `failed_retryable` goes back to `executing` with the **same** `PayPal-Request-Id`. An unknown outcome is resolved by reconcile-by-read (GET the target in PayPal and decide executed or not). The DESIGN "Try again (safe, same request key)" copy stands. | PLAN + DESIGN |
| R3 | Approve atomicity (D1) | Approve and claim happen in one conditional UPDATE `proposed → executing` plus the approval insert, in one transaction. There is no standalone `approved` resting state for agent proposals. | PLAN |
| R4 | Conflicting work (D2) | Every Proposal carries a kind-independent `subject_ref` (Dispute ID, or capture ID for refunds and accepts on that capture's Dispute; Invoice ID for reminders). Partial unique index `(epoch, subject_ref) WHERE status IN ('proposed','executing','failed_retryable')`. The refund revalidate step also rejects when an open Dispute exists on the capture. | PLAN |
| R5 | Model amounts (D10) | The model never authors money. Refunds carry `basis: full \| items \| shipping_only` plus `line_item_refs[]`, and code computes the amount. The Merchant may edit the amount at Approval; the edit is recorded in `edited_fields` and capped at the refundable remainder. | PLAN + AI-QUALITY |
| R6 | Standing Policy (D9) | NG4 is amended (REQUIREMENTS) to allow invoice-reminder policies only. Policy reminders use a deterministic template with **no model call** and no Untrusted Text. They run lazily when the queue or Brief loads and from a `/api/policies/run` route invoked by an external free cron (GitHub Actions schedule calling it with a secret header). There is no separate Render cron service. If the open-work index is hit, the policy skips that Invoice and counts the skip. Needs security-auditor sign-off at 0.5c. | PLAN + AI-QUALITY |
| R7 | Pipelines (D5) | The dispute desk, invoice chaser, risk explanations and Brief lines are pipelines (one structured-output call, no tools), triggered by explicit routes: `POST /api/disputes/:id/assess`, `POST /api/invoices/chase`, `POST /api/risk/explain`. Brief lines are cached in the DB per epoch and refreshed by an explicit "Refresh brief" action. Every model call goes through `lib/guard` reserveSpend. | PLAN |
| R8 | Brief LCP (D19) | Brief renders a deterministic template from DB-cached data first (counts, amounts, deadlines). Model-written lines stream in afterwards. | PLAN + DESIGN |
| R9 | Routes (D17) | Use DESIGN's route table: `/enter`, `/` (Brief), `/queue`, `/invoices`, `/disputes`, `/risk`, `/audit`, `/policies`, `/settings`. Risk Flags are **Attention Items, not Proposals**. They appear in the Brief and `/risk`; the queue shows Proposals only (a refund Proposal may cite a Risk Flag). Data-source mode is the env var `DISPUTE_SOURCE` (live \| simulated \| mixed); Settings displays it read-only, with no runtime toggle. | DESIGN + PLAN |
| R10 | AG Grid depth (D12) | Grid features land with the page that needs them: grouping + status bar in 0.2 (queue), master/detail Evidence Packet in 0.3, sparklines + one integrated chart (cash at risk by Attention Item type, Enterprise only) in 0.4. 0.5d is polish only. AG Grid key decision date is **Oct 20**: if there's no key by then, the Community fallback in DESIGN becomes the design. Night theme moves to the cut list. | PLAN + DESIGN |
| R11 | Disputes timeline (D14) | One probe Dispute is filed about Oct 6 to learn the sandbox lifecycle. Demo Disputes are filed Nov 3–5, before recording. The hosted judging window and the SC-11 smoke use SIM Disputes (stated in DEMO.md). The seed and dispute scripts are scoped to 0.1b. | PLAN |
| R12 | Reset demo (D8) | Reset bumps the epoch, expires the old epoch's open Proposals, and tops up fresh unrefunded seed Orders. Audit Entries are never deleted. The DESIGN reset copy says "starts a fresh demo round; history stays in the Audit Log". | PLAN + DESIGN |
| R13 | Credentials (D13) | 0.1a has a credential-free path: scaffold, CI, MSW-backed grid, Render deploy with placeholder env. P0 probes run as soon as the user's `.env` exists and results are appended to PLAN §1. | PLAN |
| R14 | Budgets (D11) | Full eval ≤ $10 (A-9). The CI smoke subset follows AI-QUALITY (8+8, ≤ $1). There is a nightly `workflow_dispatch` eval, and a full pass is required before tagging v0.3+. Paths are aligned to PLAN's layout: `src/lib/ai/**`, `src/features/*/ai/**`, and Proposal schemas in `src/features/approvals/schema.ts`. | PLAN + AI-QUALITY |
